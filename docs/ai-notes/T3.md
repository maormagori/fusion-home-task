# T3 — Analysis / LLM

## Prompts that mattered
- "Use the installed library versions (check node_modules .d.ts files)" → read `openai@7.60.0`'s
  `ResponseFormatJSONSchema` in `resources/shared.d.ts`: `json_schema.schema` is `{ [key: string]: unknown }`, so
  `z.toJSONSchema(analysisResultSchema)` passes straight through with no cast.
- "Tell the manager if z.toJSONSchema output is rejected by Ollama" → before writing the client, printed the generated
  schema and sent it with `curl` to Ollama's `/v1/chat/completions`. It uses `$schema` (draft 2020-12), `enum`,
  `minLength`, `minimum`/`maximum` and `additionalProperties: false`; Ollama accepted it and returned valid JSON.
  Nothing to escalate.

## Where the AI was wrong / low quality and how it was corrected
- First draft of the validation tests asserted with `expect(validation.ok === false && validation.error)` to get past
  the union type → correct but needs a second look to read → replaced by a `validationErrorFor(raw)` test helper that
  throws if validation unexpectedly passes and returns the error string.

## Shortcuts / tradeoffs taken
- `completion.choices[0]?.message.content`: the `?.` is there so an empty `choices` array ends up in the same
  "LLM returned an empty response" error as an empty `content`, instead of a `TypeError`. The brief says
  "throw if it is empty"; I read that as covering both.
- The JSON Schema is built once per client (`createOpenAiLlmClient`), not per call.
- Feedback delimiters are `<<<FEEDBACK>>>` / `<<<END FEEDBACK>>>`. They mitigate prompt injection; they do not prevent
  it (feedback could contain the end delimiter). Strict structured output + Zod still limit what an injected prompt can do.
- `analyzeOnce` test for `llm_error` points at `http://127.0.0.1:9/v1` (discard port, nothing listening) with
  `LLM_SDK_MAX_RETRIES=0`, so it fails fast on connection refused without Ollama.
- The LLM test checks only sentiment and "at least one feature request"; the text of the insight is not asserted
  because the model is not deterministic enough for that. Observed run: ~2.9s.

## Walkthrough for the owner
- `src/analysis/prompt.ts` — the system prompt (fields, their meaning, JSON only, ignore instructions in the feedback)
  and two builders. Worth knowing: the feedback only ever goes into the user message, wrapped in delimiters.
  `buildCorrectionMessages` returns `[assistant: raw, user: error]` for the worker to append to the conversation.
- `src/analysis/llm-client.ts` — `LlmClient` interface plus the `openai` SDK implementation. Timeouts and transport
  retries (5xx, 429, network) are the SDK's own (`timeout`, `maxRetries` from config). `response_format` sends the Zod
  schema as JSON Schema with `strict: true`, `temperature: 0`.
- `src/analysis/analyzer.ts` — `validateRawOutput` (JSON.parse, then strict Zod, errors as readable strings via
  `z.prettifyError`) and `analyzeOnce`, which turns one LLM call into an `AttemptOutcome`. Worth knowing: it never
  repairs JSON or strips fences, so a bad answer is visible as `invalid_output` and goes to the correction loop.
- How to see it work: `npm test` (`test/analysis/prompt.test.ts`, `test/analysis/analyzer.test.ts`) and, with Ollama
  running, `npm run test:llm` (`test/analysis/analyzer.llm.test.ts`).
