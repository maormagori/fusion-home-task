## Prompts that mattered
- "buildApp + real repo (temp file DB) + real queue + real LLM, through app.inject()" → three integration tests exercise submissions, persisted attempts, normalized duplicates, transport failure, manual retry, and recovery.
- "Build config with the test helpers ... build loggers with createLogger('silent')" → both working and unreachable clients use the existing config helpers; no production changes were needed.
- "plain curl + jq, readable, with a short echo before each step" → the executable smoke script submits, polls, reads detail, duplicates, and calls retry with an expected HTTP result.

## Where the AI was wrong / low quality and how it was corrected
- An initial duplicate assertion expected exactly one attempt after deduplication. That would reject a legitimate model correction → compare attempt counts before and after the duplicate instead.
- The first smoke draft printed the retry HTTP result without checking it → assert 409 for DONE or 202 for FAILED so unexpected server errors fail the script.
- The default Vitest reporter hid successful-test console output → reran with `--reporter=verbose --disableConsoleIntercept` to capture timing and attempt evidence.
- `npm install` rewrote optional dependencies in the lockfile without a dependency change → restored the lockfile.

## Shortcuts / tradeoffs taken
- After PR #7 merged, merged the integration branch into this already-pushed branch and replaced local path/status constants with `FEEDBACK_PATH`, `feedbackDetailUrl`, `feedbackRetryUrl`, and `StatusCodes`. Status values come from `feedbackStatusSchema.enum`.
- The shell demo spells wire paths and statuses directly because it is a standalone curl example. It has a configurable base URL and polling budget.
- On a healthy server the smoke demo proves retry rejection (409); the integration test proves successful FAILED → RECEIVED → DONE retry after real connection errors. No endpoint or hidden test hook was added to force failures in the running server.
- Recovery tests call the exported `recoverPendingAnalyses` used by startup; they do not kill a child server process.
- Timing console output was removed in review; the earlier measurements below remain the recorded evidence.
- Temporary SQLite files are removed after queues drain and apps close. The existing database contract has no close operation; these short-lived test connections end with the Vitest process.
