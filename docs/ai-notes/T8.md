## Prompts that mattered
- "Invoke `ui-ux-pro-max` before writing UI code and run its search scripts for this product" → ran
  `search.py "internal admin feedback dashboard minimal data-dense" --design-system --variance 2 --density 7`,
  plus `--domain style "status badge dark mode minimal"`, `--domain ux "loading empty state focus form error"` and
  `--stack react "polling list rerender"`. Results and what I did with them are in the next section.
- "Single source of models (hard rule)" → `web/` has no type for feedback, attempts, analysis, statuses or API
  bodies. `web/src/api.ts` is typed with the backend's `z.infer` types and **parses every response with the backend's
  own Zod schema**, so a contract drift shows up as an error in the UI instead of bad data. The status filter
  iterates `FEEDBACK_STATUSES`; paths come from `FEEDBACK_PATH`, `CONFIG_PATH`, `feedbackDetailUrl`, `feedbackRetryUrl`.
- Owner question mid-task: "split frontend libraries out of the backend's package.json?" → I proposed npm workspaces
  with the root staying the backend package and `web/` as a second package (no backend files move, so no conflicts
  with the two workers editing `src/` and `test/` in parallel). Approved. The coordinator added that a later refactor
  will move the models to `packages/shared`, so all model imports in `web/` go through one file, `web/src/models.ts`.

## ui-ux-pro-max: what it recommended, what I kept or dropped
| Recommendation | Kept? | Why |
|---|---|---|
| Pattern "Real-Time / Operations Landing" (hero, metrics, CTA) | Dropped | It is a marketing landing page; this is a one-page internal tool. |
| Style "Exaggerated Minimalism" (oversized 3–12rem type, weight 900) | Dropped | Meant for fashion/editorial pages. A data panel needs dense, readable text. Kept only "minimal, high contrast, whitespace". |
| Palette: primary `#1E40AF`, background `#F8FAFC`, destructive `#DC2626`, amber accent `#D97706`, ring = primary | Kept, adapted | Primary, background and ring used as is. Foreground changed from the suggested blue `#1E3A8A` to slate `#0F172A` (neutral text). Red and amber reused for the FAILED and ANALYZING badges with darker text shades for 4.5:1 contrast. Dark variants are lighter, desaturated tones, as its `color-dark-mode` rule says. |
| Fonts: Fira Sans / Fira Code from Google Fonts | Dropped | An external font request for an internal tool adds a network dependency for no functional gain. System UI stack and system monospace instead. |
| Dark-mode styles (OLED, Cyberpunk, Cinema) | Dropped | Neon/glow effects do not fit. Dark mode is the same tokens redefined under `prefers-color-scheme: dark`. |
| UX: visible focus rings, `role="alert"`/`aria-live` for errors, labels on inputs, empty states with guidance, loading → success/error on submit | Kept | All in place: `:focus-visible` outline, `role="status"` on the form notice, `role="alert"` on load and retry errors, `<label for>` on the textarea, empty states in list and detail. |
| Checklist: color not the only signal, `prefers-reduced-motion`, 44px targets, tabular numbers | Kept | Badges show the status text and a dot. The ANALYZING dot pulse is turned off under reduced motion. Rows are ≥44px buttons. The counter and percentages use tabular figures. |
| React: stable keys | Kept | Rows keyed by `id`, attempts by attempt `id`. |

## Where the AI was wrong / low quality and how it was corrected
- First `api.ts` draft had an `isDuplicateResponse(status)` helper → the submit response already has `duplicate: boolean`,
  so the helper duplicated the contract → removed it.
- Attempts with no LLM response were labelled "invalid" and showed a placeholder `<pre>`. In the FAILED screenshot this read as a
  validation failure although the call itself never returned → three labels now: "valid output", "invalid output",
  "LLM call failed" (`rawResponse === null`), and the `<pre>` only renders when there is a raw response.
- The first FAILED-state click-through left an empty favicon 404 in the console → added `<link rel="icon" href="data:,">`.
- After the workspace switch I first deleted and regenerated `package-lock.json`. The coordinator asked for that only if
  `npm ci` breaks, so I restored the lockfile and ran an incremental `npm install`. npm still pruned some optional peer
  `@emnapi/*` entries (the same thing the literals sweep saw). `npm ci --dry-run` passes; CI confirms it on Linux.

## Shortcuts / tradeoffs taken
- Not covered by the brief: the Submit button is **not** disabled for empty or over-limit text (only while sending or
  before `/config` loads), so the API's 400 message is what the user sees. The counter turns red when over the limit.
- Not covered by the brief: prev/next paging (not "load more"), because polling one fixed page with `limit`/`offset` is simpler.
- The open detail panel refreshes when the list sees the selected item change (`status:attemptCount:updatedAt`). If the
  selected item is not on the visible page (filtered out), its detail does not poll. Acceptable for a minimal UI.
- No guard against an older list response overwriting a newer one after a quick filter change. The next poll or
  click fixes it. Not added because the spec does not ask for it (no defensive code without approval).
- The CSS has the four status names and three sentiment names as attribute selectors (`[data-status='DONE']`). CSS
  cannot import from Zod, so this is the one place they are literals. TS/TSX in `web/` has none.
- `server.ts` resolves `web/dist` from its own file (`new URL('../web/dist', import.meta.url)`), so it works with
  `npm run dev` from any folder. A compiled `dist/src/server.js` would look in `dist/web/dist`. There is no start script
  for compiled output yet, so I left it.
- Error bodies: `requestJson` parses non-2xx bodies with `errorResponseSchema`. A non-JSON error (e.g. the Vite proxy with
  the API down) surfaces as a JSON parse error message. Good enough for an error state.
- Not edited (outside my file list): `CLAUDE.md` Commands and Layout and `docs/ARCHITECTURE.md` do not list the
  `web:*` scripts or the workspace yet. The README task can add them.

## Walkthrough for the owner
- `web/src/models.ts` — the only file in `web/` that imports backend models (paths, schemas, `z.infer` types).
  Worth knowing: these source files import only `zod`, so Vite can bundle them. A `db`/`fastify`/`node:*` import in them
  makes `npm run web:build` fail, which is the check.
- `web/src/api.ts` — one function per endpoint. `requestJson` fetches, throws the API's `{ error }` message on non-2xx,
  and parses the body with the backend schema (no `as` casts).
- `web/src/useFeedbackList.ts` — loads one page and polls every 2 s **only while** a visible item is RECEIVED or
  ANALYZING. The interval effect depends on that boolean, so it starts and stops by itself.
- `web/src/useFeedbackDetail.ts` — loads `GET /feedback/:id` and reloads when the `refreshKey` from the list changes.
- `web/src/App.tsx` — page state: filter, offset, selected and highlighted id. A duplicate submit selects and highlights the existing item.
- `web/src/components/` — `SubmitForm` (counter from `GET /config`, 202/200/400 notices), `FeedbackList` (filter,
  rows as buttons, pager), `FeedbackDetailPanel` (`switch` on status: in progress / `AnalysisView` / last error + Retry),
  `AttemptList` (collapsible `<details>` with raw responses in `<pre>`), `StatusBadge`.
- `web/src/styles.css` — one stylesheet. Theme tokens on `:root`, redefined for dark mode.
- `src/api/app.ts` — `uiDistPath?` option. `@fastify/static` is registered only if that folder exists, so tests and CI without a web build are unaffected.
- `src/api/feedback.routes.ts` / `feedback.schemas.ts` — `GET /config` → `{ maxContentLength }` with `configResponseSchema`.
- `package.json` / `web/package.json` — npm workspaces. Root = backend deps + `web:dev|build|typecheck` delegating to
  the `web` workspace. One `npm install`, one lockfile.
- How to see it work: `npm run web:build && npm run dev`, open http://localhost:3000. Or `npm run dev` + `npm run web:dev`
  (Vite on :5173 proxies `/feedback` and `/config` to :3000). Tests: `npm test -- test/api/static-ui.test.ts test/api/config.test.ts`.

  `03-done-detail.png`, `04-failed-retry.png` (+ `-dark`), `05-duplicate.png`, `06-after-retry-done.png`. FAILED was
